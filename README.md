## 先搞清楚一件事：你是拿来干什么的

这是最容易被忽略的一步。很多人上来就问"几核几G够用"，但其实答案完全取决于你要跑什么。

我把常见的几种场景整理一下：

- **个人博客 / 静态站**：1核1G或者2核2G，带宽10M左右，基本就够了。这种站流量不大，访客也就那么几个，杀鸡不用牛刀。
- **企业官网 / 小型动态站**：建议2核4G起步，带宽20M以上。动态站涉及数据库查询、PHP执行，内存太小会拖垮整个响应链。
- **跑 API / 小程序后端**：看并发量。低并发2核4G能扛，中高并发往4核8G走，带宽别低于30M。
- **AI 应用 / 知识库 / 本地大模型**：这是个分水岭。CPU再强也救不了显存不够，这类需求得直接看GPU套餐。
- **开发测试环境**：配置随意，能跑就行，重点在于随时能重置。

有个经验法则挺管用：**CPU核数和内存容量配比建议在1:4到1:8之间**。也就是说4核配16G、8核配32G这种比例比较健康。如果你看到"2核8G"这种配比，多半是内存吃紧型场景（比如跑数据库），而不是通用型。

## 带宽和流量：藏成本的地方就在这

CPU和内存是明面上的钱，带宽和流量才是真正容易翻车的点。

云服务商的带宽标注方式不太统一。有的是"上行/下行"分开标，比如10M上行15M下行；有的是直接给一个总带宽。**上行带宽影响的是别人访问你的速度**，这才是网站体验的关键。下行带宽大、上行带宽小，你下载爽了，用户访问还是慢。

流量这块更要看清楚。有的套餐是"不限流量"，有的是"流量包"模式。流量包模式有时候带宽更高，但**超额之后要么限速要么扣钱**，下载站、图片站、突发流量型业务都得留够余量。

> 小提示：很多服务商的流量是双向计费的，上传和下载都算。买之前一定翻一下文档。

## 几个常被问到的选择难题

**"我跑WordPress，2核2G够吗？"**

够，但会偏紧。WordPress本身不重，但加上几个插件、跑点缓存、再装个WooCommerce，2G内存很快就吃满。建议直接上2核4G那档，多出来的内存给数据库和PHP-FPM留余量，响应会顺很多。

**"带宽10M是不是太小了？"**

看你的页面有多大。一个做了CDN优化的WordPress页面，首次加载大概1-2MB，10M带宽理论上能支撑5-8个并发首屏加载。如果你日UV在几百以内，10M完全够用。但如果是图片站、视频站、或者突发流量型的内容，带宽就得往上加。

**"CPU核数重要还是内存重要？"**

对大多数Web场景来说，**内存比CPU更重要**。CPU决定你能算多快，内存决定你能同时处理多少事。一个小站CPU常年占用不到20%，但内存经常被打满。所以预算有限的话，宁可降一档CPU也要保住内存。

**"动态计费套餐是什么？要不要选？"**

动态计费是雨云的一个特色模式——基础月租很便宜，但CPU超额使用时按日额外计费（俗称"CPU电费"，内存等其他硬件不收电费）。适合那种平时CPU占用很低、偶尔突发一下的轻量业务。如果你CPU常年高负载，老老实实选固定套餐更划算。
